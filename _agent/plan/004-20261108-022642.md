# Plan 004: Step-by-step curl (copy one at a time) + M3 flow viewer with curl boxes

Created: 2026-11-08 02:26:42 UTC+7

## Goal

User request (with their Postman collection `DemoSignup.postman_collection (3).json`, their own Thai
`index.html` explainer, and a screenshot of the P1AIC canvas with "CURL1 / CURL2" boxes drawn under nodes):

1. Curl **one request per step** that can be copied and run one by one, like the Postman collection.
2. A web page that looks like the **P1AIC journey canvas** (nodes at the export x/y, outcome lines) with a
   **curl box on each step** that has a copy button.

## Findings from the user's Postman collection (verified against the real tenant)

- Page Node callbacks carry `_id`, which must be sent back and can change between responses. Generated `.sh`
  is fine (it posts the whole response back); runbook bodies written by hand were missing `_id`.
- Working headers: `Accept-API-Version: protocol=1.0,resource=2.1` and `X-Requested-With: ForgeRock`.
- Real prompts come from the server ("First Name", "Email Address") and differ from export attribute names.
- Error path: Show Error Message sends a `TextOutputCallback`; acknowledging it returns HTTP 401 "Login failure".
- Session check: `GET /am/json/serverinfo/*` gives `cookieName`; `POST .../sessions?_action=getSessionInfo`
  with header `<cookieName>: <tokenId>`.

## Decisions

- **Copyable step block** = take the last response (`resp.json`), set the inputs with jq, post it, save the new
  response. This keeps `_id`, real prompts and server values without any capture variables:
  ```bash
  jq --arg v1 "$IN_USERNAME" --arg v2 "$IN_PASSWORD" \
    '.callbacks[0].input[0].value = $v1 | .callbacks[1].input[0].value = $v2' resp.json \
  | curl -sS -X POST "$URL" -H ... -b cookies.txt -c cookies.txt -d @- | tee resp.json | jq .
  ```
  The explicit request body (Postman style) is still shown next to it for reading, now with `_id` noted.
- Variant steps show one block per variant (like Postman 04a/04b/04c) plus a line that prints which one to
  send; optional steps say when to skip.
- Viewer follows the design stack: **Preact + Vite + vite-plugin-singlefile** (pinned preact 10, vite 6).
  Build `viewer/` to one HTML template; `src/generate/viewer.ts` injects the plan JSON. UI in English;
  default view **Engineer** (curl visible), toggle to **Simple** (user did not answer; their page and drawing
  are curl-first).
- Viewer data: nodes (x/y, type, name, page children), edges (outcome, onPath), static nodes, steps with
  plain text, copy block, explicit body, expected next, variants; inner journeys as their own canvases with
  a breadcrumb (click an Inner Tree node to open it).
