## Findings from the export (input to the design decisions)

- Shape: `{ meta, trees: { <name>: { tree, nodes, innerNodes, scripts, ... } } }`. `tree.nodes[id]` holds
  `connections`, `displayName`, `nodeType`, `x`, `y`; `nodes[id]` holds the config (`_type._id`, `_outcomes`);
  PageNode config has `nodes: [{_id, nodeType, displayName}]`, child config is in `innerNodes`.
  `tree.staticNodes` has x/y for Success, Failure, `startNode`.
- Scripts: `script` is a JSON string of the source (one `JSON.parse` level here); all are next-gen
  (`evaluatorVersion` 2.0, `callbacksBuilder.*`).
- Prompts are built by concatenation (`'what is ' + a + ' + ' + b + '?'`) → scanner renders `{a}`/`{b}` placeholders.
- `test-journeys-001` / `passwordless2` use standalone Username/Password nodes (one step each, not a page).

## Decisions

- **Path cost** (Dijkstra, not plain BFS): edge = 1 + outcome penalty (preferred 0, neutral 1, negative 4) only
  for *user-controlled* nodes; *server-decided* nodes (Login Count, Query Filter, Attribute Present, Identify
  Existing User, random scripts…) have no outcome preference; entering an interactive node costs +3. This yields
  the design's Login plan (`Login Count Decision --false--> Success`, preferences page optional).
- **Variants / optional steps:** at a server-decided node on the path, each other outcome is followed (most
  interactive simple path) until it rejoins the main path. All branches 1 step → `variant` step; chosen branch
  0 steps and an alternative has steps → `optional` steps; otherwise a warning suggesting `--choose`.
- **Input variables:** `IN_USERNAME`, `IN_PASSWORD`, `IN_<ATTR>` (`preferences/x` → `IN_PREF_X`); a second
  distinct password node → `IN_NEW_PASSWORD`; other duplicates get `_2`. Scripted inputs: single-input node →
  node name minus leading verb (`Choose Channel` → `IN_CHANNEL`); multi-input → prompt words (`IN_CITY`).
- **KBA count:** not in the export → `kbaCount` in config, default 1, with a warning (open question in design).
- **Templates:** eta renders the `.sh` skeleton; per-step bash is built in TS. Templates are read from
  `src/templates` (dev/tests) or `dist/templates` (build).
- **Package manager:** npm (pnpm not installed). Node 26 locally; `engines` ≥ 20.
- `jq` is not installed on this machine: generated scripts can't be run here yet (needed for M4 e2e).
